# Desktop candidate verification

This AGPLv3 fork preserves upstream history and LICENSE/NOTICE. The desktop candidate is stacked on Android PR #10, source `830ee0ce308560de1651755d46e53f88866659ee`, and retains its Android IME, tmux and Zellij work. Build artifacts name the exact candidate commit. The upstream development baseline is `7a64f0b25a4d3adf56d4fb1fd8f76db26d41fa85` (0.58.0); no moving upstream head is used during a run.

## Sessions and keyboard

Desktop saved and quick SSH connections use one shared None / Tmux / Zellij form. None opens ordinary SSH without probing a multiplexer. `＋ New` is a separate sentinel from a remote session literally named `New`; existing targets use their stable remote identity. Missing/exited sessions fail rather than being recreated. A matching open target activates its existing tab or split pane. Explicit custom tab names take priority over the actual session name; host details remain auxiliary.

While a desktop terminal has focus, Ctrl, Alt and function-key combinations go to the terminal by default. Per-binding **Allow while terminal has focus** opts an app command in. Ctrl+C always sends SIGINT, including with a selection. Use mouse/menu clipboard actions where those bindings are reserved. Normal form editing and composition/dead/AltGr events retain their behavior. Windows WebView2 browser accelerators are disabled only while the terminal is focused and restored afterwards. No OS hooks, global hotkeys, security policy changes or new Tauri capabilities are added. OS-reserved combinations and real OS IME behavior require device testing.

## Device-local SSH authentication

The Authentication selector is opt-in. Existing vault/imported credentials remain the default. System policy and paths stay in account-scoped local UI storage and are excluded from vault/settings sync and exports. Private keys are read by the Rust backend in place; their contents never cross IPC or enter the vault. Encrypted-key passphrases are temporary per-operation answers, never saved. Reconnect can ask again. Agent authentication uses public identities and the agent signing API, without exporting private keys. Agent forwarding remains a separate, default-off setting.

System-key order: explicit paths, otherwise matching config IdentityFile entries, otherwise `~/.ssh/id_ed25519`, `id_ecdsa`, `id_rsa`. Relative paths start in `~/.ssh`. Duplicate identities are skipped. There are at most three public-key attempts and no automatic RSA retry/password fallback in this mode; a lower server MaxAuthTries may still require selecting exactly one identity. Unix private files must belong to the current user with no group/other permissions; Windows uses the current user's filesystem ACLs without elevation.

Optional config lookup supports Host globs/negation, quoted IdentityFile and first-value IdentitiesOnly. An explicit config alias can be supplied when Voltius uses the resolved endpoint. HostName/User/Port/routing remain Voltius settings. Match and Include fail closed with an actionable error; commands and shell variables are never executed or expanded. This is not complete OpenSSH-config compatibility. Agent identities matching selected `.pub` files are tried first; IdentitiesOnly restricts agent auth to those public files. Certificates, FIDO/security-key and Pageant support are not claimed.

macOS/Linux use the current process user's home and SSH_AUTH_SOCK. Windows uses its native home and `\\.\pipe\openssh-ssh-agent`, separate from WSL. macOS UseKeychain does not silently supply a passphrase. Terminal, picker preparation, reconnection, standalone SFTP, distribution probes and referenced jump hosts carry the same policy. Public-key deployment remains outside this feature and retains its existing implementation. Host-key verification remains active. Only synthetic keys, a loopback SSH fixture and an isolated OpenSSH agent are used by automated authentication tests; no user keys, agent, authorized_keys or remote servers are accessed.

## Packages and measured coverage

`.github/workflows/desktop-session-test.yml` builds macOS ARM64 (ad-hoc signed app), Windows x64 (unsigned executable/NSIS/MSI), and Ubuntu 24.04 x86_64 packages plus a restricted Flatpak. It publishes temporary Actions artifacts only: no release, notarization, Developer ID, Authenticode identity, persistent private key, paid resource or account-permission change. The Android workflow also validates the same desktop candidate commit with its existing development test signature, which is unsuitable as a long-term upgrade identity.

Linux frontend/native tests include real tmux and Zellij CLI/PTY tests and synthetic system-key/agent authentication. The browser fixture uses the production shared form, handlers and real xterm, with simulated SSH/native IPC. Browser automation does not prove native Tauri or OS IME behavior. Platform manifests record actual architecture, signatures, launch observations and hashes; read the run results before treating a check as passed.

Rocky 8.10's official native libraries cannot satisfy Tauri 2's WebKitGTK 4.1/libsoup3 requirements. The restricted Flatpak uses pinned official GNOME Platform 50 and is separately launched in the vendor-signed Rocky 8.10 cloud image under QEMU TCG with SELinux unchanged. Ubuntu success is not Rocky evidence. The Flatpak grants only window/IPC/network access: no host home, agent, Secret Service, host shell, serial or GPU device. **Host-default-key/agent authentication is unavailable in this restricted package.** No permission expansion is performed. Rocky screenshots prove only the observed startup; account/keychain, interactive terminal, real SSH/SFTP, GPU and native IME remain separate tests.

## Repeatable verification

Use Node 24.19.0, pnpm 11.5.2, the repository's Rust 1.96.0 toolchain, and locked dependencies. Review scripts before running. Start from a clean exact candidate SHA; `pnpm install --frozen-lockfile --ignore-scripts`, `cargo fmt --all --check`, `pnpm test`, `pnpm build`, `cargo test --locked --workspace`. Native tests require OpenSSH client/sftp-server, tmux, zsh and the verified Zellij tools specified in the Android/desktop workflow. Browser tools have their own locked fixture manifest; run Vite with `scripts/desktop-ui.vite.config.ts`, then `scripts/verify-desktop-ui.mjs` with a normally sandboxed installed Chrome. Do not disable a browser or WebKit sandbox to make a test pass.

Desktop CI uses `pnpm tauri build --ci --config '{"bundle":{"createUpdaterArtifacts":false}}' --target <target> --bundles <platform-bundles> -- --locked`, followed by the platform verifier. Maintenance is never advanced by these workflows. For daily synchronization, create a new candidate from the maintained branch, merge the fixed upstream dev SHA normally, preserve conflicts/failures in the candidate, run this validation, and advance maintenance only after explicit validated promotion. Never force-push or delete history. Scheduling belongs to the parent thread.

`candidate/desktop-ui-check-*` branches run the isolated browser job for UI fixture iteration. They do not constitute platform validation. Advancing the same tested commit onto `candidate/desktop-sessions-*` triggers every desktop job and Android verification again.
